Project 4 — Blue Team: Guardrails, Hardening and Detection1. Project OverviewThis project focuses on strengthening AI identity security through defensive controls, input/output guardrails, cryptographic identity verification, Auth0 hardening, and anomaly detection.The objective is to mitigate the attack scenarios identified during Project 3 — Red Team and improve the security of AI agent identity workflows.2. Project ObjectivesImplement input guardrails against malicious attack payloads.Detect and redact sensitive JWT-shaped credentials in model outputs.Establish cryptographic identity verification using Ed25519 signatures.Strengthen Auth0 token security through short-lived access tokens and refresh token rotation.Implement risk-based authentication controls.Detect suspicious AI identity activities through anomaly detection.Compare security outcomes before and after defensive controls.3. Implementation Details3.1 Input and Output GuardrailsImplemented custom security guardrails to identify and handle potentially malicious inputs.Key activities:Tested simulated malicious input patterns.Implemented deterministic input validation.Blocked suspicious inputs based on configured security rules.Implemented JWT-shaped credential detection using regular expressions.Redacted sensitive credential-like values from outputs using [REDACTED].The assessment includes local test cases and supporting evidence.3.2 Cryptographic Agent Identity BindingImplemented cryptographic identity verification using Ed25519.Key activities:Generated an Ed25519 public/private key pair.Used the private key to sign agent messages.Used the public key to verify message signatures.Tested valid signed messages.Modified a signed message to simulate tampering.Verified that tampered messages were rejected.This demonstrates message integrity and cryptographic identity verification.3.3 Auth0 HardeningImplemented authentication hardening controls using Auth0.Key activities:Configured API access token lifetime to 300 seconds.Enabled refresh token rotation.Tested reuse of an older refresh token after rotation.Evaluated rejection of the replayed refresh token.Implemented a custom risk-based Auth0 Action using configured risk conditions.Tested low-risk and high-risk authentication scenarios.3.4 Anomaly DetectionDeveloped Python-based detection logic to identify suspicious AI identity activities.The detection scenarios include:High Request Rate: Identifies unusually high API request activity.Unexpected Scope Change: Detects changes in permissions or scopes between requests.Expired Token Reuse: Identifies attempts to reuse expired tokens.Detection results are documented through test outputs and evidence.3.5 Before and After Security ComparisonCompared the baseline attack scenarios from Project 3 with the defensive controls implemented in Project 4.The comparison evaluates:Attack outcomes before defensive controls.Applied security controls.Observed outcomes after defensive controls.Changes in attack success rates.The results are based on local or synthetic test scenarios and are not a production-wide security effectiveness measurement.4. Security ConsiderationsPrivate cryptographic keys must not be committed to source control.Sensitive tokens and credentials must be protected.Environment-specific secrets should be stored securely.Access tokens should have limited lifetimes.Agent messages should be verified before processing.Defensive controls should be tested against both malicious and legitimate inputs.8. Project OutcomeThis project demonstrates defensive security mechanisms for AI identity systems through guardrails, cryptographic message verification, Auth0 token hardening, risk-based authentication, and anomaly detection.It builds on the findings from Project 3 and provides a defensive security foundation for the governance, compliance, and policy recommendations developed in Project 5.
